# Этапы 7–8. Alert Detail, governance и интеграционная граница

## Этап 7 — Explainability и audit trail

Добавлены экран Alert Detail и форма демонстрационной экспертной проверки.
Карточка показывает score, trigger threshold, целевой исход, когорту, версии
модели и данных, review status и локальное SHAP-объяснение. Эксперт может
выбрать результат review и оставить комментарий. Новая запись добавляется
только в память текущей browser session и отображается в audit trail.

Такое ограничение преднамеренно: UI ещё не содержит server-side storage, а
значит не должен создавать ложное впечатление постоянного журналирования.

## Этап 8 — Model Governance и завершение интеграции UI

Добавлен экран Model Governance с registry модели, границами использования и
сводным audit trail. Навигационная цепочка теперь имеет вид:

```text
EWS Dashboard → Alert Queue → Alert Detail → expert review → session audit trail → Model Governance
```

На всех EWS-экранах закреплено правило human-in-the-loop: Red и Amber alerts
обозначают необходимость рассмотрения, но не являются автоматическим
кредитным, надзорным или иным решением.

## Когда подключать реальные записи

На локальном компьютере уже доступны примерно 16 GB Fannie Mae данных:
обработанные панельные файлы, outcomes и воспроизводимые model samples.
Они остаются в research pipeline. Их нельзя помещать в React bundle или
передавать браузеру целиком: это избыточно, небезопасно и может нарушать
условия распространения данных.

Реальные записи подключаются только после следующего инфраструктурного
этапа — server-side API и базы audit trail. Тогда API будет выдавать
авторизованному пользователю лишь разрешённые, минимально необходимые поля
одного alert; raw file, идентификаторы и вся выборка останутся вне browser
client. До такого разрешённого и защищённого подключения используется только
synthetic demo dataset.
