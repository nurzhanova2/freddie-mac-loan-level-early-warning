# Этапы 24–25. Углубление архитектуры SupTech-прототипа

## Единый контракт безопасного alert DTO

Модуль `api/app/alert_contract.py` является единственным источником правил для
разрешённых полей approved score export и для alert DTO, доступного браузеру.
CSV-adapter использует его для валидации схемы, API `/contract` публикует тот
же список допустимых browser-полей, а сериализация alert использует тот же
контракт при формировании ответа. Это сохраняет запрет на raw Fannie Mae
файлы, стабильные идентификаторы кредита и обучающие выборки.

## Единая frontend-политика ролей

Модуль `ui/src/app/accessPolicy.js` определяет роли и правила доступа к
экранам. Sidebar, Model Governance и Administration используют одни и те же
предикаты. Backend RBAC остаётся источником принудительного контроля: новая
frontend-политика не расширяет права и не заменяет API-проверки.

## Проверка

Добавлены независимые Node-тесты role policy и расширены Python-тесты
безопасного export-контракта. Сборка React и API-интеграционные тесты входят в
стандартную процедуру проверки изменений.

## Функциональные модули EWS

Экранный router `pages/EwsPages.jsx` оставлен минимальным. Компоненты
организованы по пользовательским workflow: `features/ews/alerts`,
`features/ews/monitoring` и `features/ews/governance`. Общие примитивы
представления и lifecycle загрузки API расположены в `features/ews/shared.jsx`.
Это сохраняет единое поведение loading/error состояния, но не создаёт
абстракций для одноразовых панелей.
