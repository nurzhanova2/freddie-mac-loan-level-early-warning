# Приложение Б. Data lineage и рабочий глоссарий

## Б.1. Назначение и границы

Приложение описывает путь данных от архивной поставки до воспроизводимых
артефактов исследования. Оно не заменяет официальный file layout Fannie Mae:
наименования, коды и типы полей следует проверять по [официальному glossary и
file layout](../../sources/crt-file-layout-and-glossary.xlsx). Здесь приведены
только понятия аналитического контура и исследовательского прототипа; записи
отдельных кредитов не раскрываются.

## Б.2. Прослеживаемость данных

```text
Архив Fannie Mae Primary Dataset
        ↓  проверка структуры, ключей и SHA-256
raw ZIP / manifests
        ↓  очистка типов и дат; нормализация пропусков
очищенный 113-польный слой
        ↓  допустимые на дату t поля и 35-польная аналитическая панель
monthly panel «кредит–месяц»
        ↓  будущие окна, цензурирование и исходы 3/6/12 месяцев
размеченные аналитические панели
        ↓  временное train / validation / OOT-разделение
версии model samples и манифесты
        ↓  модели, validation-only calibration и фиксированные queue policies
метрики, SHAP, permutation importance, ALE и figures
        ↓  разрешённый score-export без raw loan-level полей
исследовательский SupTech-прототип
```

На каждом переходе сохраняются версия входного набора, конфигурация и выходной
артефакт. Архивы и панели остаются в исследовательском контуре. В браузерный
слой передаётся только разрешённый alert DTO: обезличенный идентификатор случая,
дата оценки, score, уровень сигнала, версия модели, краткое локальное
объяснение, статус экспертной проверки и, после завершения окна, наблюдаемый
исход. DTO не содержит raw-архив, идентификатор кредита Fannie Mae или полный
набор признаков.

| Слой | Основная функция | Контроль воспроизводимости |
|---|---|---|
| Raw | хранение исходной поставки | manifest и SHA-256; без перезаписи |
| Interim | технически очищенная запись | число полей, ключи «кредит–месяц», типы |
| Processed | допустимая аналитическая панель | реестр leakage и версия исхода |
| Model samples | временные train/validation/OOT подвыборки | seed, hash-правило, manifest |
| Reports | метрики, калибровка, XAI и figures | версия модели и конфигурации |
| Prototype export | безопасная витрина сигналов | allow-list полей и версия export |

## Б.3. Рабочий глоссарий

| Термин / поле | Смысл в исследовании | Использование |
|---|---|---|
| Cohort / vintage | квартал выдачи кредита, например `2008Q1` | стратификация и проверка устойчивости |
| Observation month | месяц, в котором формируется прогноз | дата *t*; граница допустимости признаков |
| Loan–month | наблюдение «кредит–месяц» | единица анализа |
| Current delinquency status | статус обслуживания на дату *t* | формирование базы риска и признаки |
| Formal adverse | будущий статус 90+ дней просрочки | исход `formal_adverse_hm` |
| Early deterioration | переход из current в 30+ дней просрочки | исход `early_deterioration_hm` |
| Horizon | будущие месяцы для поиска исхода | 3, 6 или 12; основной — 6 |
| Censoring | неполное окно или ненаблюдаемый статус | не маркируется как не-событие |
| Leakage | информация, недоступная на дату *t* | исключается до обучения и оценки |
| Zero Balance Code / Effective Date | сведения о прекращении кредита | для проверки/исхода, не предиктор |
| Train / validation / OOT | периоды подгонки, калибровки, оценки | 2006–2016 / 2017–2020 / 2021–2025, v01 |
| Calibration | согласование score и частоты события | isotonic regression, только validation |
| Red alert | top-1% очереди `formal_adverse_6m` | приоритет экспертной проверки |
| Amber alert | top-5% очереди `early_deterioration_6m` | мониторинговый сигнал |
| Lead time | месяцы между сигналом и событием | операционная характеристика |
| SHAP | вклад признака в score модели | поведение модели, не причинный эффект |
| Permutation importance | потеря качества после перестановки признака | проверка глобальной важности |
| ALE | усреднённый профиль связи признака и score | проверка формы зависимости |

## Б.4. Связь с методологическим аудитом

Определения исходов, цензурирование, состав фактических обучающих выборок,
параметры моделей, калибровка и Red/Amber policy зафиксированы в [приложении
А](appendix_a_methodological_audit.md). Решения об исключении полей содержатся
в [реестре leakage](../../../data/dictionaries/fannie_2008q1_leakage_register_v01.csv),
а сводная нумерация доказательных артефактов — в [перечне таблиц и
рисунков](list_of_tables_and_figures.md).
