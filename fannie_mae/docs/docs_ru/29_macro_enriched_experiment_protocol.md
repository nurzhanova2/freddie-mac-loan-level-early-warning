# 29. Протокол macro-enriched эксперимента

## Цель и статус

Настоящий протокол задаёт отдельный эксперимент для проверки того, изменяет
ли добавление доступного на дату скоринга макроэкономического и регионального
контекста качество прогнозирования двух исходов: `formal_adverse_6m` и
`early_deterioration_6m`. На момент фиксации протокола это не результат
исследования. Витрина ещё не присоединена к выборкам, модели не
переобучались, поэтому результаты v01 и v02 остаются базовыми.

## Сопоставимый дизайн

Для baseline и macro-enriched вариантов используются одни и те же выборки
`model_samples_v01`: train — январь 2006 г. — декабрь 2016 г.; validation —
январь 2017 г. — декабрь 2020 г.; независимый out-of-time период — январь
2021 г. — сентябрь 2025 г. Гиперпараметры и способ калибровки выбираются
только по validation. OOT-набор используется однократно для итоговой оценки.

В качестве неизменной точки сравнения сохраняется XGBoost v01. Для
macro-enriched ветки будут оценены XGBoost, LightGBM и CatBoost. Выбор
кандидата производится по PR-AUC validation-выборки при контроле ROC-AUC и
Brier score; это правило зафиксировано до обучения.

## Point-in-time витрина

Витрина строится из ALFRED vintage snapshots для даты `monthly_reporting_period`.
В неё входят эффективная ставка федеральных фондов, безработица по США,
безработица штата и FHFA HPI штата. Для каждой записи обязательно хранятся
идентификатор ряда, запрошенная vintage-дата, дата исходного наблюдения и
время извлечения. Это позволяет проверить, что при скоринге не использовалась
опубликованная позднее величина или её последующая ревизия.

Региональные признаки соединяются по `property_state`. В выборках присутствуют
50 штатов, DC, GU, PR и VI. Если региональный ряд для территории не доступен
на соответствующую дату, его значение остаётся пропущенным, а в модель может
поступить только отдельный индикатор доступности. Замена такого пропуска
средним по штатам запрещена.

## Проверки до обучения

Перед обучением должны быть выполнены четыре условия: (1) аудит покрытия
витрины по месяцам, географиям и рядам; (2) проверка, что даты наблюдений и
vintage не превосходят дату score; (3) фиксация итогового списка признаков;
(4) сохранение manifest, seed и конфигурации каждого запуска. Лишь после
этого рассчитываются ROC-AUC, PR-AUC, Brier score, калибровка, характеристики
Red/Amber alerts, lead time и объём очереди.
